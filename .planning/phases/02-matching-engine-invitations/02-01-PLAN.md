<threat_model>

## Trust Boundaries

| Boundary                                   | Description                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------- |
| Firebase token -> Express                  | Untrusted bearer identity crosses into the API.                           |
| Founder request -> Idea/Match query        | Request IDs and filters must not grant access to another founder's idea.  |
| Candidate profile -> public match response | Stored profile data crosses into a privacy-sensitive response projection. |

## STRIDE Threat Register

| Threat ID | Category               | Component               | Disposition | Mitigation Plan                                                                                                    |
| --------- | ---------------------- | ----------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------ |
| T-02-01   | Spoofing               | matching routes         | mitigate    | Require existing Firebase `authenticateUser` and resolve Mongo User by `req.user.uid`.                             |
| T-02-02   | Elevation of privilege | matchingController      | mitigate    | Verify `Idea.createdBy` equals the authenticated founder before reading requirements or writing Match snapshots.   |
| T-02-03   | Information disclosure | candidate projection    | mitigate    | Select only the established public profile fields; exclude email, Firebase UID, and private founder fields.        |
| T-02-04   | Tampering              | Match snapshots         | mitigate    | Derive score and requirements snapshot server-side and upsert with validated ObjectIds and taxonomy-shaped inputs. |
| T-02-SC   | Tampering              | dependency installation | accept      | No new package is planned; use Node built-ins and existing dependencies.                                           |

</threat_model>
