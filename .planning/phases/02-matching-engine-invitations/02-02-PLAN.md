<interfaces>
Invitation identity is `{ ideaId, toCandidate }`; retain one current record per pair with a unique compound index. Fields are `fromFounder`, `toCandidate`, `ideaId`, `role`, optional bounded `message`, optional `matchId`, `matchContext`, `status`, response/withdraw timestamps, and Mongoose timestamps.
Allowed statuses are exactly `Pending`, `Accepted`, `Declined`, and `Withdrawn`. Resend changes only `Declined -> Pending` in place and refreshes the match context; accepted/withdrawn states are not reversible.
Use the existing `authenticateUser` middleware and resolve `req.user.uid` to User for actor checks. Use Idea.createdBy for founder ownership. Return safe User/Idea projections and never Firebase tokens or email in public candidate payloads.
</interfaces>
</context>

<threat_model>

## Trust Boundaries

| Boundary                                | Description                                                        |
| --------------------------------------- | ------------------------------------------------------------------ |
| Firebase token -> invitation actor      | Untrusted identity selects sender/recipient role.                  |
| Request body -> invitation document     | Role, candidate, idea, message, and match IDs are untrusted input. |
| Invitation response -> team eligibility | Candidate state crosses into later team formation.                 |

## STRIDE Threat Register

| Threat ID | Category               | Component               | Disposition | Mitigation Plan                                                                                         |
| --------- | ---------------------- | ----------------------- | ----------- | ------------------------------------------------------------------------------------------------------- |
| T-02-04   | Elevation of privilege | invitationController    | mitigate    | Check founder ownership, recipient identity, profile type, and actor direction on every operation.      |
| T-02-05   | Tampering              | invitation status       | mitigate    | Use enum validation plus status-conditional `findOneAndUpdate`; unique index handles send races.        |
| T-02-06   | Information disclosure | invitation read/list    | mitigate    | Apply actor predicate before lookup and populate only safe idea/profile fields.                         |
| T-02-07   | Repudiation            | matchContext/timestamps | mitigate    | Persist immutable-in-practice send snapshot, status timestamps, sender, recipient, and idea references. |
| T-02-SC   | Tampering              | dependency installation | accept      | No new package is planned.                                                                              |

</threat_model>
